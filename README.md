# npm OIDC public smoke test

This repository is a public, manually triggered smoke test for npm trusted publishing against the public npm registry. It checks an npm CLI branch, tag, or commit and runs `npm dist-tag`, `npm publish`, or `npm stage publish` without a long-lived npm token.

The workflow does not use the npm sandbox registry, private npm repositories, custom runners, or repository secrets. It only accepts `https://registry.npmjs.org/`.

Each npm command has its own reusable workflow:

| Workflow | Command |
| --- | --- |
| `npm-dist-tag.yml` | `npm dist-tag list`, `add`, or `remove` |
| `npm-publish.yml` | `npm publish` |
| `npm-stage-publish.yml` | `npm stage publish` |

There are two central workflows:

| Workflow | Use |
| --- | --- |
| `npm-oidc-smoke.yml` | Minimal full suite accepting only a package and npm CLI ref |
| `npm-oidc-custom.yml` | Full-options dispatcher for selecting a command, package, user, registry, versions, tag, and CLI ref |

The smoke workflow publishes a unique version, adds/lists/removes a dist-tag, and stages a second unique version. Its only dispatch inputs are the package and npm CLI branch, tag, or commit. The CLI ref defaults to `latest`.

All three command workflows can also be run directly with `workflow_dispatch`. A direct run uses that command workflow's filename for trusted publisher validation, while a run through the central dispatcher uses `npm-oidc-smoke.yml`.

## What it tests

The smoke sequence is:

| Step | Behavior |
| --- | --- |
| Publish | Publishes `0.0.0-oidc.<run-id>.<run-attempt>.publish` with `oidc-smoke-publish` |
| Dist-tag add | Adds `oidc-smoke` to the published version |
| Dist-tag list | Confirms authenticated tag listing works |
| Dist-tag remove | Removes `oidc-smoke` |
| Stage publish | Stages `0.0.0-oidc.<run-id>.<run-attempt>.stage` with `oidc-smoke-stage` |

## npm package setup

The target package must already exist on npm and must be configured with a GitHub Actions trusted publisher:

| npm trusted publisher field | Value |
| --- | --- |
| Organization or user | GitHub owner of this repository |
| Repository | GitHub repository name |
| Workflow filename | `npm-oidc-smoke.yml` for one-click smoke or `npm-oidc-custom.yml` for custom runs |
| Environment | Leave blank |

Enable the trusted publisher permissions needed for the operation you want to test:

* Allow publish for `npm publish`.
* Allow stage publish for `npm stage publish`.
* The npm CLI branch from [npm/cli#10038](https://github.com/npm/cli/pull/10038) adds OIDC exchange support to `npm dist-tag`.

The package's `repository.url` must point to this public GitHub repository. Packages generated by the workflow use that URL automatically. npm validates the calling workflow for reusable workflow runs, so add trusted publisher connections for each entry point you intend to use: `npm-oidc-smoke.yml`, `npm-oidc-custom.yml`, or the directly dispatched command workflows.

## Run the workflow

1. Open **Actions**.
2. Select **npm OIDC smoke test**.
3. Select **Run workflow**.
4. Enter the package.
5. Keep `latest` or enter the npm CLI branch, tag, or commit to test.

The npm CLI ref defaults to `latest`. For pull request 10038, override it with `feat/dist-tag-oidc` or the exact commit SHA `071f18169e22963117045ac0319b4c414f781e26`.

Published and staged versions consume permanent semver values. The workflow combines the GitHub run ID and run attempt so normal runs and reruns receive different versions. Smoke runs for the same package are serialized by the workflow concurrency group, preventing simultaneous dist-tag mutations. A staged version remains pending after the workflow and must be approved or rejected separately by a maintainer with 2FA.

The repository does not contain a root npm package or hardcode an npm package name or version. Each publishable package is built entirely in the runner's temporary directory from the workflow package input and a generated unique version. The generated manifest declares `"files": ["index.js"]`, and the generated `index.js` exports an empty object. Its tarball contains only the generated `package.json` and `index.js`. Repository files and npm CLI source files are not included.

## Materialize a package locally

The local materialization script writes the same generated fixture to the ignored `package/` directory:

```sh
node scripts/materialize-package.mjs @owner/package-name 1.0.0
```

The version defaults to `1.0.0` when omitted. Set `GITHUB_REPOSITORY=owner/repository` to include a repository URL in the generated manifest. When it is unset or `false`, the repository field is omitted. The package name is always supplied at runtime and is not hardcoded in this repository.

The final `report` job writes a GitHub Actions job summary with the result of every command and fails unless all five command checks succeeded.

You can trigger and follow the smoke test from GitHub CLI:

```sh
gh workflow run npm-oidc-smoke.yml \
  -f package=@example/npm-oidc-smoke \
  -f cli_ref=latest

sleep 3
run_id=$(gh run list --workflow npm-oidc-smoke.yml --event workflow_dispatch --limit 1 --json databaseId --jq '.[0].databaseId')
gh run watch "$run_id" --exit-status
gh run view "$run_id" --json conclusion,url --jq '{conclusion, url}'
```

## Security properties

The workflow has only `contents: read` and `id-token: write` permissions. It uses a GitHub-hosted runner, does not configure `NODE_AUTH_TOKEN`, serializes runs per package, validates all inputs before registry mutation, and generates the package in the runner's temporary directory.
